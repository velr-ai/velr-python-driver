gds.guide

Velr GDS guide

Run these Cypher procedures on an embedded connection with GDS enabled. Use the Velr Python driver guide or the Velr Rust driver guide for connection setup and result handling. Run each Cypher block as a separate query. Apply the queries in each example in order. Start with a fresh sample database unless the example uses data from an earlier section.

Use CALL gds.list() to discover the procedures and scalar functions on your connection. To look up a family such as PageRank, run CALL gds.list('pageRank').

A projection belongs to the connection that creates it. Drop it when you finish or close the connection to release its projections. Drop and recreate a named projection to include changes to the database, or project the updated data under another name. Each connection with GDS has a 512 MiB memory budget by default. Set Gds(memory_limit_bytes=...) in Python or Gds::new().with_memory_limit_bytes(...) in Rust to change that budget.

Project a named graph

Pass gds.graph.project a name, a node selection, a relationship selection, and an optional configuration map. Use a fresh name or drop the existing projection before reusing its name. Close open result tables to release any memory they retain after a drop.

  • nodeProjection accepts a label, a list of labels, '*' for all nodes, or a map of projected labels to options. All forms select nodes with any of the specified labels. In a map, label defaults to the projected label. Declare labels explicitly to select them with nodeLabels in an algorithm call. A wildcard-only projection exposes no named labels.
  • In a node option map, properties accepts a name, a list of names, or a map. Use properties: {seed: 'storedCommunity'} to project storedCommunity as seed. Use properties: {seed: {property: 'storedCommunity', defaultValue: 0}} to supply a default for missing values. property defaults to the alias. To load properties on every selected node, use nodeProperties in the fourth argument with the same syntax. Use the same source property and default if you reuse a property alias for multiple labels.
  • Each projected scalar property holds Integers or finite Floats of one type. Set a default of the same type, such as 0 for Integers or 0.0 for Floats. Missing values are null when you omit the default or set it to null. A property with no values or default is an Integer column. Label-specific properties are null on nodes outside their selected labels. Use gds.util.asNode(nodeId) to read a node's current database properties.
  • A projected vector property accepts stored VECTOR values with FLOAT32 or FLOAT64 coordinates and Lists of Floats. Every projected node must have a finite vector of the same positive width. Use a nonempty finite numeric list as defaultValue for missing vectors on selected nodes. Include the vector property on every projected label. An optional positive Integer dimensions declares the width. For estimates with explicit node and relationship counts, supply dimensions or a vector default so memory reflects the vector width.
  • relationshipProjection accepts a type, a list of types, '*', or a map of aliases to type names or option maps. Include each source type once. Use the wildcard by itself. Both endpoints must match the node selection. Declare original types by name or alias to select them in an algorithm call.
  • In a relationship option map, type defaults to the alias. Set orientation independently for each type. NATURAL follows stored direction and is the default. REVERSE follows the opposite direction, and UNDIRECTED follows both. relationshipCount counts both directions for each undirected relationship, including each undirected self-loop.
  • To project numeric weights on an original relationship type, set properties to a property name, a list of distinct names, or a map from aliases to property definitions. For example, properties: ['weight', 'capacity'] retains both names, and properties: {cost: 'weight', limit: 'capacity'} exposes them as cost and limit. Use {property: 'weight', defaultValue: 1.0} as an alias definition to supply a default for missing values. If you omit property, the property name defaults to the alias. Stored weights and defaults must be finite numbers. Types can use different source properties and defaults under the same alias.
  • aggregation accepts 'NONE' and 'DEFAULT'. Both keep parallel relationships and self-loops. indexInverse accepts a Boolean for directed projections. Omit it or set it to false on undirected projections.
  • The fourth argument also accepts readConcurrency, a positive Integer with default 4. Projection uses one thread.

Use stored community seeds

Project the optional Integer storedCommunity property on Person nodes as seed, then pass that alias to Label Propagation. For this projection, nodes without a stored community start with seed 0.

CREATE (:Person {name: 'Alice', storedCommunity: 7})-[:KNOWS]->
       (:Person {name: 'Bob'}), (:Person {name: 'Carol'})

CALL gds.graph.project('seeded_people', {
  Person: {properties: {seed: {property: 'storedCommunity', defaultValue: 0}}}
}, 'KNOWS')

CALL gds.labelPropagation.stream('seeded_people', {seedProperty: 'seed'})
YIELD nodeId, communityId
RETURN gds.util.asNode(nodeId).name AS name, communityId ORDER BY name

Rank nodes by two weight aliases

Create three accounts with a transfer and a payment from the same account.

CREATE (alex:WeightedAccount {name: 'Alex'}),
       (blair:WeightedAccount {name: 'Blair'}),
       (casey:WeightedAccount {name: 'Casey'}),
       (alex)-[:TRANSFER {amount: 3, transfers: 1}]->(blair),
       (alex)-[:PAYMENT {payments: 3}]->(casey)

Project volume and frequency on both relationship types. The payment has no stored total, so its volume uses the default of 1.0.

CALL gds.graph.project('account_flows', 'WeightedAccount', {
  WIRE: {type: 'TRANSFER', properties: {volume: 'amount', frequency: 'transfers'}},
  CARD: {type: 'PAYMENT', properties: {
    volume: {property: 'total', defaultValue: 1.0}, frequency: 'payments'
  }}
})

Run PageRank twice on the same projection, choosing one weight alias per call. Blair ranks first by volume, and Casey ranks first by frequency.

CALL gds.pageRank.stream('account_flows', {
  relationshipTypes: ['WIRE', 'CARD'], relationshipWeightProperty: 'volume'
})
YIELD nodeId, score
RETURN gds.util.asNode(nodeId).name AS account, score
ORDER BY score DESC, account

CALL gds.pageRank.stream('account_flows', {
  relationshipTypes: ['WIRE', 'CARD'], relationshipWeightProperty: 'frequency'
})
YIELD nodeId, score
RETURN gds.util.asNode(nodeId).name AS account, score
ORDER BY score DESC, account

Rank nodes across relationship orientations

Create three people with a directed endorsement and a collaboration.

CREATE (ada:MixedRank {name: 'Ada'}),
       (blair:MixedRank {name: 'Blair'}),
       (casey:MixedRank {name: 'Casey'}),
       (ada)-[:ENDORSES {strength: 3}]->(blair),
       (ada)-[:COLLABORATES {intensity: 1}]->(casey)

Project the endorsement in its stored direction and the collaboration in both directions. Give both types the weight alias weight.

CALL gds.graph.project('mixed_rank', 'MixedRank', {
  ENDORSES: {orientation: 'NATURAL', properties: {weight: 'strength'}},
  COLLABORATES: {orientation: 'UNDIRECTED', properties: {weight: 'intensity'}}
})

Run weighted PageRank across both types. With these settings, Ada receives 0.75, Blair receives 0.6875, and Casey receives 0.5625.

CALL gds.pageRank.stream('mixed_rank', {
  relationshipTypes: ['ENDORSES', 'COLLABORATES'],
  relationshipWeightProperty: 'weight', dampingFactor: 0.5, maxIterations: 2
})
YIELD nodeId, score
RETURN gds.util.asNode(nodeId).name AS person, score ORDER BY person

Rank nodes within projected label groups

Create a graph with overlapping labels. Blair belongs to both selected groups, and Drew belongs to one group and has no relationships.

CREATE (ada:LabelRankMember {name: 'Ada'}),
       (blair:LabelRankMember:LabelRankReviewer {name: 'Blair'}),
       (casey:LabelRankReviewer {name: 'Casey'}),
       (:LabelRankReviewer {name: 'Drew'}),
       (guest:LabelRankGuest {name: 'Guest', storedRank: -1.0}),
       (ada)-[:RECOMMENDS {rating: 3}]->(blair),
       (ada)-[:CO_REVIEWS {strength: 1}]->(casey),
       (ada)-[:RECOMMENDS {rating: 100}]->(guest)

Project all three labels and give both relationship types the weight alias weight.

CALL gds.graph.project('label_rank', {
  Member: {label: 'LabelRankMember'},
  Reviewer: {label: 'LabelRankReviewer'},
  Guest: {label: 'LabelRankGuest'}
}, {
  RECOMMENDS: {properties: {weight: 'rating'}},
  CO_REVIEWS: {orientation: 'UNDIRECTED', properties: {weight: 'strength'}}
})

Rank nodes in the union of Member and Reviewer across both types. Blair appears once, Drew receives a score, and the edge to Guest is outside the selection.

CALL gds.pageRank.stream('label_rank', {
  nodeLabels: ['Member', 'Reviewer'],
  relationshipTypes: ['RECOMMENDS', 'CO_REVIEWS'],
  relationshipWeightProperty: 'weight', dampingFactor: 0.5, maxIterations: 2
})
YIELD nodeId, score
RETURN gds.util.asNode(nodeId).name AS person, score ORDER BY person

Use the same selection to estimate the call. It contains four nodes and three relationship arcs, including both directions of the co-review.

CALL gds.pageRank.stream.estimate('label_rank', {
  nodeLabels: ['Member', 'Reviewer'],
  relationshipTypes: ['RECOMMENDS', 'CO_REVIEWS'],
  relationshipWeightProperty: 'weight', dampingFactor: 0.5, maxIterations: 2
})
YIELD nodeCount, relationshipCount, bytesMax
RETURN nodeCount, relationshipCount, bytesMax

Save the same scores as a new groupRank property on the projection. The property contains Float scores for the four selected nodes and null for Guest.

CALL gds.pageRank.mutate('label_rank', {
  nodeLabels: ['Member', 'Reviewer'],
  relationshipTypes: ['RECOMMENDS', 'CO_REVIEWS'],
  relationshipWeightProperty: 'weight', dampingFactor: 0.5, maxIterations: 2,
  mutateProperty: 'groupRank'
})
YIELD nodePropertiesWritten
RETURN nodePropertiesWritten

CALL gds.graph.nodeProperty.stream('label_rank', 'groupRank')
YIELD nodeId, propertyValue
RETURN gds.util.asNode(nodeId).name AS person, propertyValue AS score
ORDER BY person

Find the closest score for each selected node with kNN on the same projection. kNN requires a value for each selected node, so use the same label aliases.

CALL gds.knn.stream('label_rank', {
  nodeLabels: ['Member', 'Reviewer'], nodeProperties: 'groupRank', topK: 1
})
YIELD node1, node2, similarity
RETURN gds.util.asNode(node1).name AS person,
       gds.util.asNode(node2).name AS neighbor, similarity
ORDER BY person

Save the same weighted scores to storedRank. The procedure writes four properties, and Guest keeps the existing value of -1.0.

CALL gds.pageRank.write('label_rank', {
  nodeLabels: ['Member', 'Reviewer'],
  relationshipTypes: ['RECOMMENDS', 'CO_REVIEWS'],
  relationshipWeightProperty: 'weight', dampingFactor: 0.5, maxIterations: 2,
  writeProperty: 'storedRank'
})
YIELD nodePropertiesWritten
RETURN nodePropertiesWritten

Catalog operations and scalar functions

Call Result and arguments
CALL gds.graph.project(graphName, nodeProjection, relationshipProjection [, configuration]) Returns graphName, nodeProjection, relationshipProjection, nodeCount, relationshipCount, and projectMillis. Use a nonempty String name other than '*'. The configuration defaults to {}.
CALL gds.graph.project.estimate(nodeProjection, relationshipProjection [, configuration]) Estimates the memory required for a projection. Returns Integer nodeCount, source relationshipCount before applying orientation, bytesMin, and bytesMax, String requiredMemory and treeView, Map mapView, and Float heapPercentageMin and heapPercentageMax.
CALL gds.graph.list([graphName]) Lists matching projections. The String defaults to '*', which lists every graph on the connection. Returns graphName, database, memoryUsage, sizeInBytes, nodeCount, relationshipCount, and schema. An unknown name returns no rows.
CALL gds.graph.exists(graphName) Accepts a String and returns graphName and Boolean exists.
CALL gds.graph.drop(graphName [, failIfMissing]) Accepts a String name and returns the same columns as gds.graph.list for the removed projection. Boolean failIfMissing defaults to true. Pass false to return no rows when the name is absent.
CALL gds.graph.nodeProperty.stream(graphName, nodeProperty) Accepts two Strings and returns nodeId and propertyValue for a projected scalar or Float vector property, including FastRP embeddings.
CALL gds.graph.nodeProperties.stream(graphName, nodeProperties [, nodeLabels [, configuration]]) Returns one row per selected node and property, with nodeId, nodeProperty, and propertyValue. Accepts a String or List of Strings for the properties.
CALL gds.graph.relationshipProperty.stream(graphName, relationshipProperty [, relationshipTypes [, configuration]]) Streams Float scores or weights from the catalog, with sourceNodeId, targetNodeId, relationshipType, and propertyValue. Supply a projected property name and a type alias or list of aliases. The default ['*'] selects the catalog types that have that property. Supports original projected types and types added by Node Similarity and kNN.
CALL gds.graph.nodeProperties.drop(graphName, nodeProperties [, configuration]) Removes numeric or vector properties from the catalog graph. Accepts a String or List of Strings and returns propertiesRemoved, graphName, and nodeProperties. The count includes entries with null values. Boolean failIfMissing defaults to true. Set it to false to skip missing properties.
CALL gds.graph.nodeProperties.write(graphName, nodeProperties [, nodeLabels [, configuration]]) Writes present Integer and Float values and Float vectors for selected nodes. Vectors are stored as VECTOR values with FLOAT64 coordinates. Accepts a name, a map from projected names to database names, or a list of those forms. Returns writeMillis, propertiesWritten, graphName, nodeProperties, and configuration.
CALL gds.list([name]) Accepts a case-sensitive String substring. Omit it or pass '' to list everything. Returns name, description, signature, and type.
gds.version() Scalar function returning the add-on version as a String. Use RETURN gds.version() AS version.
gds.util.asNode(nodeId) Scalar function resolving an exact Integer database ID to a node in the current query. It returns null for a missing node or a null ID. For a property map, bind the node first with WITH gds.util.asNode(nodeId) AS n RETURN properties(n).

For gds.graph.project.estimate, use the same selectors and properties as project. Set relationshipProperties to apply the same weight definitions to each relationship type and omit properties from the relationship selectors. Integer nodeCount and relationshipCount default to -1. With both defaults, the estimate uses counts from the database. Set a nonnegative count to estimate a hypothetical input. The other count is zero if left unspecified. The memory percentages are relative to the connection's GDS budget. treeView and mapView break down the estimated bytes for graph structure and node properties. The configuration also accepts positive Integer concurrency and readConcurrency with default 4, optional String jobId with default null, and Boolean logProgress with default true.

For gds.graph.nodeProperties.stream and gds.graph.nodeProperties.write, pass a projected label alias or a list of distinct projected aliases as nodeLabels. Both calls use the union of label membership recorded at projection time. Use '*' or ['*'] to select all nodes. Stream returns null for missing values. Write preserves existing database values for excluded nodes and selected nodes with a missing projected value. Use distinct property names when streaming or dropping properties. Give each write destination a distinct name.

nodeProperties.stream, relationshipProperty.stream, nodeProperties.drop, and nodeProperties.write accept positive Integer concurrency with default 4. The two stream procedures accept jobId as a String or null (the default) for compatibility. nodeProperties.stream also accepts listNodeLabels: false, which is the only supported value. The write procedure accepts positive Integer writeConcurrency, which defaults to concurrency.

Run project, catalog drop, and mutate outside explicit transactions. Algorithm and catalog write calls require a writable connection and participate in the database transaction.

Algorithm modes

Call an algorithm with CALL gds.<algorithm>.<mode>(graphName [, configuration]). The graph name is a String, and the configuration map normally defaults to {}. Use constants or bound parameters. For example, look up a source node with MATCH and pass its Integer ID to a pathfinding call.

Mode Behavior
stream Returns result rows for the application to read. Use YIELD to select columns and ORDER BY when you need a specific order.
stats Returns one summary row without saving results.
mutate Saves results in the named graph. Use the algorithm's configuration to name the results, and read them with the catalog property procedures.
write Saves node properties or creates relationships in the database. Use the algorithm's configuration to name the properties or relationship type.
<mode>.estimate Estimates managed memory for the specified mode and named graph. Use the mode's configuration, including its required properties. Returns Integer nodeCount, relationshipCount, bytesMin, and bytesMax. All families with estimates also return String requiredMemory except Degree, WCC, and PageRank.

Estimates cover the additional GDS memory needed for a call. The existing projection and other retained results also count toward the connection's limit. A multiple-type estimate includes the combined view's memory in bytesMax. Any memory the estimate itself requires counts toward the same limit.

Save a result for further analysis

Project the people and their KNOWS relationships from the community seed example.

CALL gds.graph.project('people', 'Person', 'KNOWS')

Estimate the memory needed to store PageRank scores in that projection.

CALL gds.pageRank.mutate.estimate('people', {mutateProperty: 'rank'})
YIELD bytesMin, bytesMax
RETURN bytesMin, bytesMax

Run the analysis and read the saved property from the projection.

CALL gds.pageRank.mutate('people', {mutateProperty: 'rank'})

CALL gds.graph.nodeProperty.stream('people', 'rank')
YIELD nodeId, propertyValue
RETURN nodeId, propertyValue AS rank ORDER BY rank DESC, nodeId

Use write to calculate PageRank and save it on the database nodes. Drop the projection when you finish analyzing it.

CALL gds.pageRank.write('people', {writeProperty: 'pageRank'})
YIELD nodePropertiesWritten
RETURN nodePropertiesWritten

CALL gds.graph.drop('people')

Common options

The algorithm tables add to these options. Unknown keys raise an error.

Option Type and default
concurrency Positive Integer. Defaults to 4, or 1 for depth-first search and the Graphalytics procedures. Algorithms run on one thread.
nodeLabels List of Strings. The default ['*'] selects all projected nodes. List distinct projected label aliases to select their union in stream, stats, mutate, and write. The same selection applies to the corresponding estimates.
relationshipTypes List of Strings. The default ['*'] selects all original projected relationships. List distinct original type aliases or types added by Node Similarity or kNN mutate, such as ['LIKES', 'SIMILAR']. Each edge with both endpoints in the node selection contributes in its projected direction, including parallel edges and both orientations of undirected edges. A selection is undirected only when every selected type is undirected. A weighted algorithm requires relationshipWeightProperty to name a property alias shared by every selected type, including all original types when you use ['*']. Types with different weight aliases or no weight can coexist on the same graph.
jobId String or null. Defaults to null. Accepted as a compatibility option.
logProgress Boolean. Defaults to true. Accepted as a compatibility option.
mutateProperty, writeProperty String names for results saved by mutate or write. Use a new projected property name for mutateProperty. Supply writeProperty to name the database property. HITS uses suffixes, and Node Similarity and kNN also require a relationship type.
writeConcurrency Positive Integer for write and write.estimate. Defaults to 4 for Degree, WCC, PageRank, Triangle Count, and Local Clustering Coefficient. Other write modes inherit concurrency when omitted. Writes run on one thread.

Label membership comes from the projection's snapshot. Each matching node appears once, including isolated nodes, and keeps its database ID and projected properties. Filtered writes save node properties on selected nodes or create relationships between selected nodes, depending on the algorithm. Estimates report the selected counts and include memory needed to build the filtered view.

Filtered numeric mutations add properties to the original projection. They keep the algorithm's Integer or Float result type, with null for excluded nodes. nodePropertiesWritten counts the values saved for selected nodes. mutate.estimate reports the filtered node and relationship counts and budgets each saved property across all projected nodes.

When the selected labels match zero nodes, nodePropertiesWritten is zero. WCC, SCC, unweighted Degree, Triangle Count, and Local Clustering Coefficient publish an all-null property. The other supported filtered mutations create a property when the selection contains nodes.

Algorithm families

Each family below supports stream, stats, mutate, and write, with an .estimate for each mode. For example, use gds.wcc.stream to read component IDs, or gds.wcc.write.estimate to estimate the memory needed to save them.

Centrality

Family Stream columns Configuration and behavior
gds.degree nodeId, Float score orientation is a case-insensitive String. 'NATURAL' counts outgoing arcs and is the default, including for null. 'REVERSE' counts incoming arcs and 'UNDIRECTED' counts both ends. Optional String relationshipWeightProperty defaults to null. When supplied, only positive weights contribute to the sum. Unweighted mutate stores an Integer. Weighted mutate and both write variants store Floats.
gds.pageRank nodeId, Float score Float dampingFactor defaults to 0.85 in [0, 1). Positive Integer maxIterations defaults to 20 and finite nonnegative Float tolerance defaults to 1e-7. Accepts projected nonnegative weights through relationshipWeightProperty.
gds.articleRank nodeId, Float score Uses the PageRank options and defaults and accepts null for dampingFactor, maxIterations, and tolerance to select their defaults. maxIterations accepts 1 through 2147483647. ArticleRank uses the graph's average out-degree when distributing influence.
gds.eigenvector nodeId, Float score Integer maxIterations defaults to 20 and accepts 1 through 2147483647. Finite nonnegative Float tolerance defaults to 1e-7. Both accept null to select their defaults. Accepts projected nonnegative weights through relationshipWeightProperty.
gds.hits nodeId, Map values Requires a directed projection. Integer hitsIterations defaults to 20 and accepts 0 through 536870911. String authProperty and hubProperty name the two Float fields and default to 'auth' and 'hub'. The names must be distinct and contain no whitespace. Case-insensitive String partitioning accepts 'AUTO' (default), 'RANGE', or 'DEGREE'. A supplied relationshipWeightProperty must match a projected alias. Scores use topology.
gds.betweenness nodeId, Float score Exact unweighted betweenness. Optional Integer samplingSize defaults to null and, when supplied, must cover every projected node. Optional Integer samplingSeed defaults to null and has no effect on all-source execution. relationshipWeightProperty must be omitted or null.
gds.closeness nodeId, Float score Unweighted closeness. Boolean useWassermanFaust defaults to false when omitted or null. Set it to true to apply Wasserman–Faust normalization for reachable nodes.
gds.closeness.harmonic nodeId, Float score Unweighted harmonic centrality based on incoming shortest-path distances.

For HITS, set mutateProperty or writeProperty to a String suffix, which defaults to ''. For example, {mutateProperty: '_hits'} saves auth_hits and hub_hits with the default base names. With nodeLabels, mutate publishes both score columns together on the original projection. Both scores are null for excluded nodes. nodePropertiesWritten counts two values per selected node. gds.hits.mutate.estimate requires both the named graph and a configuration map, even when the map is empty. Its estimate accounts for both score properties.

Personalize or scale rank scores

PageRank, ArticleRank, and Eigenvector all accept sourceNodes, scaler, and relationshipWeightProperty. Choose a projected weight alias for the call. Omit it or use null for unweighted scores.

sourceNodes is an exact nonnegative Integer ID or a list of those IDs in the projection. The default is null, which uses uniform initialization. PageRank and ArticleRank also accept a list of [nodeId, bias] pairs with finite nonnegative biases. The last bias for a repeated ID wins. An explicit empty list yields zero scores for PageRank and ArticleRank and uses uniform initialization for Eigenvector.

scaler transforms completed scores before reporting or saving them. Use a case-insensitive String or a map with a String type. The default 'NONE' leaves scores as computed.

Scaler Transform
MAX Divide by maximum absolute score.
MINMAX Subtract the minimum and divide by the range.
MEAN Subtract the mean and divide by the range.
CENTER Subtract the mean.
STDSCORE Subtract the mean and divide by the population standard deviation.
L1NORM, L2NORM Normalize by the corresponding vector norm.
LOG Take the natural logarithm of the score plus offset. The optional finite numeric offset defaults to 0 and the sum must be positive. For example, {type: 'LOG', offset: 1}.

Connectivity and communities

Family Stream columns Configuration and behavior
gds.wcc nodeId, Integer componentId Weakly connected components treat relationships as undirected for connectivity. Each component's ID is its lowest database node ID.
gds.scc nodeId, Integer componentId Strongly connected components follow relationship direction and use each component's lowest database node ID. Set Boolean consecutiveIds to true to relabel components from zero. Defaults to false.
gds.labelPropagation nodeId, Integer communityId Integer maxIterations defaults to 10 and accepts 1 through 2147483647. Accepts String seedProperty, nodeWeightProperty, and relationshipWeightProperty, each defaulting to null. Seeds are Integer catalog properties. Node weights must be present and finite.
gds.louvain nodeId, nullable List of Integers intermediateCommunityIds, Integer communityId Requires an UNDIRECTED projection. Integer maxIterations and maxLevels each default to 10 and accept 1 through 2147483647. Finite nonnegative Float tolerance defaults to 0.0001. Accepts String seedProperty and relationshipWeightProperty, each defaulting to null.
gds.leiden nodeId, nullable List of Integers intermediateCommunityIds, Integer communityId Requires an UNDIRECTED projection. Integer maxLevels defaults to 10 and accepts 1 through 2147483647. Finite Float tolerance, gamma, and theta default to 0.0001, 1.0, and 0.01. Tolerance must be nonnegative. Gamma and theta must be positive. Optional Integer randomSeed defaults to null and uses seed 0 when omitted. Accepts String seedProperty and relationshipWeightProperty, each defaulting to null.

For Label Propagation, Louvain, and Leiden, minCommunitySize is a nonnegative Integer that defaults to 0. It filters which community IDs stream returns or write saves. The write summary still describes all computed communities. The option is available in stream, write, and their estimates. consecutiveIds defaults to false. Set it to true to renumber communities from zero. Leave it false when specifying seedProperty.

Without seedProperty, Label Propagation starts each node with its own ID as its label. Missing seeds receive distinct labels outside the supplied seed IDs. When set, nodeWeightProperty scales the vote contributed by each node.

Louvain and Leiden require nonnegative Integer seeds and nonnegative relationship weights. Their Boolean includeIntermediateCommunities defaults to false. Set it to true in stream or stats, or in those modes' estimates, and leave consecutiveIds set to false. Stream returns null in intermediateCommunityIds when the option is off. Mutate and write save only the final community ID.

Neighborhood structure

Family Stream columns Configuration and behavior
gds.kcore nodeId, Integer coreValue Requires an UNDIRECTED projection. Counts parallel relationships individually and a self-loop twice. Ignores weights.
gds.triangleCount nodeId, Integer triangleCount Requires an UNDIRECTED projection. Nonnegative Integer maxDegree defaults to 9223372036854775807. Nodes above this cutoff return -1 and their triangles are excluded. labelFilter is a List of Strings and must be [], the default.
gds.localClusteringCoefficient nodeId, Float localClusteringCoefficient Requires an UNDIRECTED projection. Optional String triangleCountProperty defaults to null. Supply a complete Integer catalog property to reuse valid triangle counts.

Triangle Count and Local Clustering Coefficient use unique neighbors, ignore loops and weights, and count parallel relationships as one adjacency. To reuse triangle counts, run Triangle Count in mutate mode and select that property using triangleCountProperty. Its values must be nonnegative and fit each node's degree, so use counts computed without a degree cutoff that produced -1.

Except for HITS, stats, mutate, and write return Integer preProcessingMillis, computeMillis, postProcessingMillis, and Map configuration plus the fields below. Mutate and write also return Integer nodePropertiesWritten and mutateMillis or writeMillis. HITS omits postProcessingMillis.

Family Additional fields
Degree, Betweenness, Closeness, Harmonic Map centralityDistribution

Node Similarity

gds.nodeSimilarity.stream(graphName, configuration) returns Integer database node IDs node1 and node2 and their Float similarity. The score measures shared outgoing neighbors. Parallel relationships to the same neighbor count once, and a self-loop counts the node among its own neighbors. Each pair compares two different nodes. Set the projection's relationship orientation to choose which neighbors the procedure uses.

Option Default Accepted values and behavior
similarityMetric 'JACCARD' Case-insensitive String. Jaccard divides the shared count by the union size. 'COSINE' divides it by the geometric mean of the two degrees. 'OVERLAP' divides it by the smaller degree.
degreeCutoff 1 Positive Integer minimum number of distinct neighbors for both nodes.
upperDegreeCutoff 2147483647 Positive Integer maximum number of distinct neighbors for both nodes. Set it to at least degreeCutoff.
similarityCutoff 1e-42 Number between 0 and 1, inclusive. Keep scores at or above this threshold. Use 0 to also allow pairs with no shared neighbors.
topK 10 Positive Integer. Keep up to this many highest-scoring matches per node1. For tied scores, a smaller node2 ranks first.
topN 0 Nonnegative Integer. Keep up to this many highest-scoring rows after applying topK. Use 0 for no global limit. Ties rank by ascending node1, then node2.

Leave relationshipWeightProperty unset or pass null for the unweighted comparison. A pair can appear in both directions because the procedure applies topK independently to each source. Use gds.nodeSimilarity.stream.estimate(graphName, configuration) with the same options to estimate memory.

gds.nodeSimilarity.stats(graphName, configuration) reports one row for the same options as stream. similarityPairs counts the directed pairs that stream returns. similarityDistribution describes those scores with min, max, mean, population standard deviation (stdDev), and the nearest-rank percentiles p1, p5, p10, p25, p50, p75, p90, p95, p99, p999 (99.9th percentile), and p100. When the pair count is zero, all distribution values are null. The row also includes nodesCompared, timings, and the effective configuration. Use gds.nodeSimilarity.stats.estimate with the same options to estimate memory.

gds.nodeSimilarity.mutate(graphName, configuration) adds the stream's directed pairs and their Float scores to the named projection. Set mutateRelationshipType to a new relationship type and mutateProperty to the score property name. The mutation updates the catalog atomically. With nodeLabels, the selection applies to the nodes being compared and their neighbors. Each new relationship connects two selected nodes. gds.graph.list shows the new type on the original projection. Use gds.nodeSimilarity.mutate.estimate with the same configuration. Its counts describe the selected graph, and its memory estimate includes the new type across the full projection.

The mutate summary reports relationshipsWritten, nodesCompared, similarityDistribution, timings, and the effective configuration. Use relationshipTypes to select the added type for another algorithm. For algorithms that accept weights, set relationshipWeightProperty to the score property name.

gds.nodeSimilarity.write(graphName, configuration) creates one directed database relationship from node1 to node2 for each pair the stream would return. Set writeRelationshipType and writeProperty to name the relationship type and the Float score property. Each successful call creates new relationships in the calling transaction. If any edge or score write fails, the whole batch rolls back. Writes run serially. writeConcurrency is accepted and defaults to concurrency. Use gds.nodeSimilarity.write.estimate with the write configuration to estimate memory.

The write summary reports relationshipsWritten, nodesCompared, similarityDistribution, timings, and the effective configuration.

Embeddings and nearest neighbors

gds.fastRP.stream(graphName, configuration) returns each selected Integer nodeId and its embedding as a List of Floats. Set positive Integer embeddingDimension. iterationWeights is a list of finite numbers and defaults to [0.0, 1.0, 1.0]. It weights successive outgoing-neighborhood averages. nodeSelfInfluence adds a contribution from the node's own initial vector and defaults to 0.0. An empty iterationWeights requires nonzero nodeSelfInfluence. The initial vectors are scaled by outgoing degree raised to normalizationStrength, which defaults to 0.0. Set relationshipWeightProperty to a projected alias containing finite nonnegative weights to average using the sum of outgoing weights.

Use Integer randomSeed for reproducible embeddings. Omit it or pass null to use seed 0. nodeSelfInfluence and normalizationStrength must be finite numbers. Use propertyRatio: 0.0 and featureProperties: [], the only supported values, to create embeddings from graph structure. gds.fastRP.stats returns nodeCount, preProcessingMillis, computeMillis, and configuration. gds.fastRP.mutate saves vectors in the catalog under a new mutateProperty. With nodeLabels, nodePropertiesWritten counts the selected nodes and the property streams as null for excluded nodes. Combine nodeLabels with relationshipTypes to select both nodes and relationships. A selection with no nodes leaves the catalog unchanged. The mutate estimate includes storage for the full projection's embedding column when the call publishes a property. gds.fastRP.write saves embeddings to the database property named by writeProperty as VECTOR values with FLOAT64 coordinates. Writeback supports 1 through 65,535 coordinates per vector. Mutate and write return the same columns as stats plus nodePropertiesWritten and mutateMillis or writeMillis, respectively. All four gds.fastRP modes have a matching .estimate.

gds.knn.stream(graphName, configuration) searches all distinct node pairs using catalog properties and returns node1, node2, and Float similarity. Set nodeProperties to a property name, a nonempty map from names to metrics, or a nonempty list combining both forms. Metric names are case-insensitive. Each selected node must have a finite value for every requested property. Use the same nodeLabels with gds.knn.stream or gds.knn.mutate to use embeddings produced by a filtered FastRP mutation. Each property contributes equally to the score.

Property Metrics and score
Integer or Float scalar DEFAULT computes 1 / (1 + absolute difference).
Float vector DEFAULT and COSINE map cosine to [0, 1]. PEARSON maps correlation to the same range. EUCLIDEAN computes 1 / (1 + Euclidean distance). Zero norm or zero variance gives 0.5 for cosine or Pearson, respectively.

Positive Integer topK defaults to 10 and limits matches per source. Finite similarityCutoff accepts [0, 1] and defaults to 0. Equal scores prefer the lower target ID. Use sampleRate: 1.0 and deltaThreshold: 0.0, the only supported values. Optional Integer randomSeed defaults to null and is accepted for compatibility. Use gds.knn.stream.estimate with the same options to estimate memory.

gds.knn.stats(graphName, configuration) takes the same options as stream and returns one summary row. similarityPairs counts the directed pairs after cutoff and top-k selection. similarityDistribution reports the minimum, maximum, mean, population standard deviation (stdDev), and the same nearest-rank percentiles as Node Similarity. When the pair count is zero, all distribution values are null. Use gds.knn.stats.estimate with the same options to estimate memory.

gds.knn.mutate(graphName, configuration) atomically adds the stream's directed pairs and their Float scores to the named projection. Set mutateRelationshipType to a new relationship type and mutateProperty to the score property name. With nodeLabels, every new relationship connects two selected nodes. The type is available on the original projection, and gds.graph.list shows it in the schema and counts the added relationships. Use gds.knn.mutate.estimate with the same configuration. Its counts describe the selected graph, and its memory estimate includes the new type across the full projection. Choose the type with relationshipTypes and the Float scores with relationshipWeightProperty when running weighted PageRank or pathfinding.

gds.knn.write(graphName, configuration) creates one directed database relationship from node1 to node2 for each pair the stream would return. Required Strings writeRelationshipType and writeProperty name the relationship type and the Float score property. Each successful call creates new relationships. The entire batch rolls back if an edge or score write fails. The write runs serially in the calling transaction. writeConcurrency is accepted and defaults to concurrency. Use gds.knn.write.estimate with the write configuration to estimate memory.

The stats, mutate, and write summaries include similarityDistribution, nodesCompared, timings, and the effective configuration. Mutate and write report the created relationship count in relationshipsWritten. nodePairsConsidered counts ordered comparisons before cutoff and top-k selection. A successful exhaustive search reports ranIterations: 0 and didConverge: true.

Pathfinding

All calls in this section accept a named graph and a configuration map. sourceNode is required and must be an exact nonnegative Integer node ID in the projection. The same ID rules apply to targets. Dijkstra, Delta-Stepping, A*, and Yen's algorithm use unit edge costs when relationshipWeightProperty is omitted or null. To use finite nonnegative weights, set it to the projected String alias.

Procedure Configuration and result
gds.bfs.stream targetNodes accepts an Integer or list of Integers. Use [] (the default) or null to traverse without targets. With targets, traversal stops at the first visited target. maxDepth is an inclusive Integer hop limit. It defaults to -1. A negative value or null allows unlimited depth. Returns sourceNode, nodeIds in visit order, and path, which links visits with virtual NEXT relationships.
gds.bfs.stats Takes the same options as gds.bfs.stream. Returns preProcessingMillis, computeMillis, postProcessingMillis, and configuration.
gds.bfs.stream.estimate, gds.bfs.stats.estimate Estimate the corresponding mode using its configuration.
gds.dfs.stream Uses the targetNodes and maxDepth options from gds.bfs.stream. Depth follows the current branch. Returns sourceNode, nodeIds in depth-first visit order, and path with virtual NEXT relationships.
gds.dfs.stream.estimate Estimates managed memory using the same configuration as depth-first search.
gds.shortestPath.dijkstra.stream Supply either targetNode as an Integer or targetNodes as an Integer or nonempty list of Integers. Defaults are null and [] respectively. Returns one row per distinct reachable target with index, sourceNode, targetNode, totalCost, nodeIds, costs, and path.
gds.allShortestPaths.dijkstra.stream Returns the same columns for all reachable nodes, including the source, without a target option.
gds.allShortestPaths.delta.stream Returns the same columns for all reachable nodes, including the source. delta is a finite positive bucket width and defaults to 2.0.
gds.shortestPath.astar.stream Requires a single Integer targetNode and String aliases latitudeProperty and longitudeProperty. Returns the same columns as Dijkstra source-target for a reachable target.
gds.shortestPath.yens.stream Requires a single Integer targetNode. Set positive Integer k to the maximum number of paths. The default is 1. Returns the same columns as Dijkstra source-target, with one row per path.
gds.shortestPath.dijkstra.stream.estimate, gds.allShortestPaths.dijkstra.stream.estimate Estimate the corresponding mode using its configuration.
gds.allShortestPaths.delta.stream.estimate Estimates managed memory using the same configuration as Delta-Stepping stream.
gds.shortestPath.astar.stream.estimate Estimates managed memory using the same configuration as A* stream.
gds.shortestPath.yens.stream.estimate Estimates managed memory using the same configuration as Yen's stream.

Dijkstra, Delta-Stepping, A*, and Yen's algorithm return Float cumulative costs starting at 0.0 at the source. The paths include virtual relationships with an individual Float cost. index is zero-based. Use ORDER BY targetNode when consuming multiple destinations in target order.

Explore a graph depth first

Depth-first search follows outgoing relationships in reverse projected order and visits each node once. It follows a branch until it reaches the inclusive maxDepth limit or has no further unvisited neighbors, then backtracks. The source has depth zero. Each node's first visit determines its depth. Relationship weights are ignored. Create sample stations for the pathfinding examples.

CREATE (a:Station {code: 'A', latitude: 0.0, longitude: 0.0}),
       (b:Station {code: 'B', latitude: 0.0, longitude: 1.0}),
       (c:Station {code: 'C', latitude: 1.0, longitude: 0.0}),
       (d:Station {code: 'D', latitude: 1.0, longitude: 1.0}),
       (a)-[:ROUTE {distance: 2.0}]->(b),
       (a)-[:ROUTE {distance: 1.0}]->(c),
       (b)-[:ROUTE {distance: 2.0}]->(d),
       (c)-[:ROUTE {distance: 2.0}]->(d)

CALL gds.graph.project('routes', 'Station', 'ROUTE')

Read the start and end IDs and bind the resulting Integers as $sourceId and $targetId in the pathfinding calls below.

MATCH (start:Station {code: 'A'}), (finish:Station {code: 'D'})
RETURN id(start) AS sourceId, id(finish) AS targetId

CALL gds.dfs.stream('routes', {sourceNode: $sourceId, maxDepth: 2})
YIELD nodeIds, path
RETURN nodeIds, [station IN nodes(path) | station.code] AS stations

Find routes from one source with Delta-Stepping

Project the relationship costs with an alias such as cost, then bind $sourceId to the start station's node ID. Delta-Stepping groups tentative distances into buckets of width delta and runs on one thread. Changing the width can change which path is returned when several paths have the same cost.

CALL gds.graph.project('weighted_routes', 'Station', {ROUTE: {properties: {cost: 'distance'}}})

CALL gds.allShortestPaths.delta.stream('weighted_routes', {
  sourceNode: $sourceId,
  delta: 2.0,
  relationshipWeightProperty: 'cost'
})
YIELD targetNode, totalCost, path
RETURN targetNode, totalCost, [station IN nodes(path) | station.code] AS stations
ORDER BY targetNode

Find a route with A*

Project both coordinates for each selected node. The columns accept Integer or finite Float values in degrees. Latitude must be in [-90, 90] and longitude in [-180, 180]. A* uses these coordinates to guide the search and returns totalCost in the units of the configured edge weights.

CALL gds.graph.project('stations',
  {Station: {properties: {lat: 'latitude', lon: 'longitude'}}},
  {ROUTE: {properties: {cost: 'distance'}}})

Bind $sourceId and $targetId to the IDs of the start and end stations.

CALL gds.shortestPath.astar.stream('stations', {
  sourceNode: $sourceId,
  targetNode: $targetId,
  latitudeProperty: 'lat',
  longitudeProperty: 'lon',
  relationshipWeightProperty: 'cost'
})
YIELD totalCost, path
RETURN totalCost, [station IN nodes(path) | station.code] AS stations

Find alternative routes with Yen's algorithm

Use a named projection such as stations above. Yen's algorithm assigns a zero-based index to each of up to k paths in nondecreasing total cost. Each path visits a node at most once. Parallel relationships count as separate routes, so rows may report the same node sequence and costs. An unreachable target yields no rows. Use ORDER BY index to return the routes in search order.

CALL gds.shortestPath.yens.stream('stations', {
  sourceNode: $sourceId,
  targetNode: $targetId,
  k: 3,
  relationshipWeightProperty: 'cost'
})
YIELD index, totalCost, path
RETURN index, totalCost, [station IN nodes(path) | station.code] AS stations
ORDER BY index
