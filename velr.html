velr

Python package for the embedded Velr property-graph database.

Import the public connection, exception, value, and result types from velr::

from velr import Velr, VelrError

with Velr.open() as db:
    with db.exec_one("RETURN 1 AS answer") as table:
        print(table.to_records())

Use parameterized run, exec_one, and exec methods for application queries. A connection or result context closes its handle; a transaction context rolls back unless explicitly committed. Scoped savepoint contexts release on success and roll back on an exception. Copied cells, paths, records, dataframes, Arrow exports, and explain snapshots survive parent handle closure.

Keep active result/transaction handles on their creating thread. An idle connection with no live children can move between threads, but operations on one connection must not overlap. CancellationToken can be signaled from another thread; query deadlines use seconds, with None meaning no deadline and 0 expiring immediately.

Database/query failures raise VelrError during execution or result consumption. Catch its subclasses for query, constraint, contention, read-only, migration, handle-state, and query-stop failures. category and detail identify classified failures; optional phase, explanation, hint and position provide context. Positions are ErrorPosition named tuples with one-based line and display-cell column coordinates, preserving ordinary tuple operations. report and str(error) retain the full diagnostic; message retains its explanation behavior. status_code is the native status, and code retains the cancellation/deadline strings. Invalid host values, optional packages, and file operations can raise their standard Python exceptions.

velr.guide provides extended workflows and velr.query_language documents supported syntax/functions. Optional Arrow, pandas, Polars, and NumPy methods state their package prerequisites in their API documentation.

Package-level names are loaded on first access. Importing velr or its reference modules does not load the native runtime or optional dataframe packages. Accessing a driver name loads velr.driver and can report missing runtime requirements. Existing from velr.driver import ... imports remain supported and return the same objects.

class VelrError ( builtins.RuntimeError ) :

Base exception for Velr query, database, and result-handle failures.

Catch this exception around both execution and result consumption. Errors can surface when a query starts, a stream advances, or rows are read. str(error) and error.args retain the original human-readable diagnostic. Catch a subclass or inspect category and detail to handle failures without matching diagnostic wording.

Attributes
  • category:: Stable runtime category, such as "ConstraintVerificationFailed", or None when unavailable. New categories may be added by newer runtimes.
  • detail:: Stable category-specific reason, such as "DeleteConnectedNode", or None. Applications must allow unknown detail values.
  • phase:: "compile" or "runtime" for classified query failures, otherwise None. A failure's phase is independent of when it is fetched.
  • message:: Human-readable explanation. Older runtimes provide the original diagnostic when a separate explanation is unavailable. Wording can change.
  • explanation:: Alias of message for the concise explanation, consistent with the remote Python client. Older runtimes can supply the full diagnostic.
  • report:: Complete rendered diagnostic, identical to str(error). Preserves the original exception arguments independently of the explanation.
  • hint:: Optional human-readable remediation text, or None.
  • position:: Optional ErrorPosition in the complete submitted query, with line and column attributes. Tuple indexing, unpacking, and equality with (line, column) remain supported. Both coordinates are one-based; columns count Unicode display cells. None means the runtime cannot identify a single source position.
  • retryable:: Whether the runtime identifies a potentially transient condition. True does not guarantee that repeating a write, script, or transaction is safe. Resolve the condition and retry at the documented operation or transaction boundary. Unclassified failures default to False.
  • status_code:: Numeric C ABI status for a native failure, or None for Python-generated failures. This is separate from the cancellation-only code property.
  • sqlite_errorcode:: SQLite's extended numeric result code when available, otherwise None.
  • sqlite_errorname:: SQLite's symbolic result-code name when available, otherwise None.
  • io_kind:: Portable filesystem failure kind, such as "not_found" or "permission_denied", when supplied by the runtime.
  • os_code:: Original platform error number for a filesystem failure, or None.
  • operation:: Failed filesystem operation, such as "open" or "create", when known.
  • path:: Database path associated with a filesystem failure, or None. Native filesystem failures retain a corresponding OSError in __cause__ when an original platform error number is available.
  • Older runtimes without structured diagnostics still raise VelrError and
  • expose native status_code and cancellation/deadline subclasses. Other
  • structured fields remain unavailable rather than being inferred from text.
  • Invalid Python arguments can raise TypeError or ValueError; optional
  • packages and file operations retain their ordinary Python exceptions.

class CancellationToken:

Signal query cancellation from any thread.

Pass the token as cancellation= when starting a query. Cancelling it signals every query using it, including deferred table and row reads. A cancelled token stays cancelled and causes later queries using it to stop. Create a fresh token for independent work. Construct it with no arguments. cancel() requests a stop without waiting for executing queries to finish; a query may finish before observing the signal. Check both execution and fetch errors for VelrError.code == "query.cancelled". The token is thread-safe; connections and active result handles remain subject to their own thread rules.

def cancel(self) -> None:

Signal a stop and return None. Repeated calls are safe.

Calls may come from any thread. The query or result reader that observes the stop raises VelrError with code == "query.cancelled". This call does not wait for completion or invalidate previously copied results.

def as_python( self, *, decode_text: bool = True, parse_json: bool = False, encoding: str = 'utf-8', errors: str = 'strict'):

Convert this copied cell to a Python value.

Scalar cells return None, bool, int, or float. Python integers preserve the full signed 64-bit result. With the defaults decode_text=True and parse_json=False, TEXT and JSON return strings. decode_text=False returns copied bytes for TEXT and unparsed JSON.

parse_json=True decodes JSON cells into Python values even when decode_text=False; it does not parse ordinary TEXT cells. Lists/maps become lists/dicts, and graph entities use their JSON data representation. Paths are JSON lists here; table to_rows()/to_records() preserve Path.

class ExplainTrace:

An EXPLAIN or EXPLAIN ANALYZE trace.

An explain trace can be traversed incrementally using the *_meta and *_count methods, or fully materialized with snapshot().

Keep the parent connection or transaction open while reading the trace. Explicitly closing the parent closes the trace, even if Python still holds a reference to it. Keep the trace on its creating thread.

Use close() when you are done, or use the trace as a context manager.

All plan/step/statement/detail indexes are zero-based. Out-of-range indexes and operations on a closed trace raise VelrError; negative or noninteger indexes can also raise Python range/type errors. snapshot() and rendered strings/bytes are owned Python data that survive trace closure. Obtain traces from Velr.explain() or VelrTx.explain() rather than constructing them.

def close(self) -> None:

Close the explain trace handle.

Repeated calls are harmless. Existing snapshots and rendered data remain usable.

Return the nonnegative number of top-level plans.

Tables yielded by this stream are valid while it remains open. Closing or exhausting the stream closes its still-open tables and row iterators.

The stream keeps its parent transaction alive for as long as the stream itself is open.

Do not construct streams directly; obtain them from exec(). Use a context manager to ensure cleanup, especially when stopping before exhaustion.

def next_table(self) -> Optional[Table]:

Return the next Table, or None after stream exhaustion/closure.

The table is owned by this stream and must be consumed or exported while the stream is open. Reaching end-of-stream closes it and any remaining child tables. Query errors, wrong-thread access, or a closed parent raise VelrError. A closed stream returns None only while its parent remains open.

def iter_tables(self):

Iterate over remaining transaction-scoped result tables.

Each yielded table is closed automatically after the iteration step completes.

Consume each table inside the loop body: advancing or closing the generator closes the previous table. Use a stream context manager when stopping early. Execution errors propagate as VelrError.

def close(self) -> None:

Close this stream and any still-open tables and row iterators it produced.

Repeated calls are harmless. The parent connection/transaction remains open. After stream closure next_table() returns None while its parent remains open; a closed parent instead raises VelrError. Call on the creating thread; cross-thread access raises VelrError.

class Table:

One result table.

A table provides:

  • column metadata via column_count() and column_names()
  • row access via iter_rows()
  • convenience export to Arrow, pandas, Polars, and IPC bytes

Keep the producing connection/transaction open while reading. A table from exec() also requires its producing stream to remain open; stream exhaustion closes its remaining tables. Explicit parent closure closes the table and its row iterators. Keep active handles on their creating thread.

Obtain a table from exec_one() or a stream. Close it explicitly or use a context manager. Operations on a closed table raise VelrError. Exports materialize data and return objects that remain usable after this table closes.

Arrow IPC and dataframe exports infer column types from the result values. Cypher lists, maps, nodes, relationships, and paths become JSON strings in Arrow UTF-8 columns. Numeric columns may use integer or floating-point types; incompatible value kinds in one column become strings. Nulls remain nulls, and empty/all-null columns use UTF-8 string types. Inspect the exported schema before assigning application-specific dtypes. Use to_rows() or to_records() for decoded Python lists and dictionaries.

def to_rows(self, columns=None):

Return the table as plain Python row lists.

This materializes the result for application code as lists, dicts, strings, numbers, booleans, and None. Cypher lists and maps are returned as Python lists and dicts; graph entities are dictionaries and paths become Path, including inside lists/maps. Plain lists of entities remain lists. Integer values preserve signed 64-bit precision. Nonfinite numeric results, when produced by the query, remain Python float NaN/infinity rather than JSON strings. Use this method when the caller intends to read the whole result.

By default all columns from the query result are returned. columns can name projected TEXT columns that contain serialized list/map documents and should be decoded into Python dict/list values. Ordinary Cypher strings stay strings unless selected here. Prefer expressing result projection in Cypher with RETURN.

columns accepts a column name or a sequence of names/zero-based indexes, such as [0] for the first column. A nonzero scalar index also works; scalar 0 is treated as an empty selection, so use [0] for that column. Unknown names, invalid indexes/types, or malformed selected JSON raise validation/decoding errors. The returned rows remain usable after the table closes. This materializes the whole result; use iter_rows() for incremental cell access. Closed, busy, wrong-thread handles, observed cancellation/deadlines, and export failures raise VelrError.

def to_records(self, columns=None):

Return the table as plain Python dict records.

This materializes the result as a list of dictionaries keyed by result column name. It is the named counterpart to to_rows(); its scalars, lists, maps, entity dictionaries, and Path values follow that method. Collected records remain usable after parent handles close. Use bind_records() for records with its supported field types.

Result column names must be unique. columns follows to_rows() and can decode selected serialized list/map text columns into Python values.

Duplicate result column names raise ValueError; a closed table raises VelrError. Selected TEXT-column validation and JSON errors follow to_rows(). Cypher queries reject duplicate result aliases with VelrError before a table is created; give projected expressions unique aliases in RETURN.

class Savepoint:

A savepoint within a transaction.

Keep this handle and its transaction on their creating thread, with the transaction and connection open. A savepoint context releases on normal exit and rolls back/releases on an exception. An exception is not suppressed; a cleanup failure can replace it.

Scoped savepoints are handle-owned:

  • dropping the handle closes the savepoint
  • release() releases it
  • rollback() rolls back to it and releases it

Named savepoints are transaction-owned:

  • dropping the returned Python handle does not remove the named savepoint
  • release() on a named handle releases that named savepoint
  • rollback() on a named handle rolls back to that named savepoint and releases it
  • VelrTx.rollback_to(name) rolls back to a named savepoint, discards any newer named savepoints, and keeps the target named savepoint active
def release(self) -> None:

Release this savepoint while retaining its changes in the transaction.

This does not commit the outer transaction. Repeated calls on a closed handle are harmless. Named savepoints must be released in reverse creation order; invalid or wrong-thread operations raise VelrError. Returns None. A named marker consumed through its transaction can make further handle operations fail even when the Python handle still exists.

def rollback(self) -> None:

Undo changes after this savepoint, then release it.

The outer transaction remains active. This differs from VelrTx.rollback_to(name), which keeps the target named savepoint active. Calling this on a closed or already-consumed handle raises VelrError; release() and close() have different repeated-call behavior. Runtime failures also raise VelrError. Returns None on success.

def close(self) -> None:

Close this handle without committing the outer transaction.

An active unnamed scoped savepoint is rolled back and released. Closing a named handle leaves its transaction-owned savepoint active; use release(), rollback(), or the transaction's named-savepoint methods to change it. Repeated calls are harmless. Prefer a with block when you want release on success and rollback on an exception.

class VelrTx:

A transaction handle.

Use commit() to persist writes or rollback() to discard them. Only one transaction may be active on its connection. Writable transactions reserve the writer slot; use a separate read-only connection for snapshots while another connection writes. Use transaction methods for work in its scope.

If used as a context manager, a still-open transaction is rolled back on exit. Use savepoint() for scoped savepoints and savepoint_named() for transaction-owned named savepoints.

Obtain a transaction from Velr.begin_tx(). Committing, rolling back, or closing it closes its child handles. Query/binding operations after transaction end raise VelrError. Do not share transactions between threads.

def run( self, cypher: str, *, max_result_rows: int | None = None, params: Mapping[str, typing.Any] | None = None, timeout: float | None = None, cancellation: CancellationToken | None = None) -> None:

Execute a query or script inside the transaction and discard results.

max_result_rows controls how many rows Velr emits while this method drains result tables:

  • None preserves the default behavior and drains all rows.
  • 0 preserves table metadata but emits no rows.
  • n emits at most n rows from each result table.

Existing Cypher LIMIT clauses still apply. The option caps emitted result rows only; it does not make the query read-only, cancel execution, or skip write side effects.

params binds openCypher parameters out of band. Query text uses $name and mapping keys omit the leading $. Supported values are None, booleans, signed 64-bit integers, finite floats, strings, lists/tuples, and mappings with string keys. Values are passed as Cypher values, so strings are never interpreted as query text. Limit nested lists/maps to 64 levels. Convert other Python values to these accepted types; construct temporal/spatial Cypher values in the query with bound strings or maps.

cypher must be NUL-free Unicode text, optionally a semicolon-separated script.

timeout is a finite, nonnegative number of seconds (not a bool). Its single deadline covers execution and any deferred table and row reads. None leaves it unset and 0 expires immediately. Pass a CancellationToken as cancellation to request a stop, including from another thread. The call that observes the stop raises VelrError with code query.deadline_exceeded or query.cancelled.

Raises
  • TypeError: If the row cap is not an int or None, params is not a mapping or None, a parameter value has an unsupported type, timeout is not a number or None, or cancellation is not a CancellationToken or None.
  • ValueError: If max_result_rows is negative, a parameter name is empty or starts with $, an integer is outside the Cypher INTEGER range, a float is not finite, nesting exceeds the supported limit, or timeout is negative, nonfinite, or outside the supported range.
  • OverflowError: If the row cap exceeds 2**64 - 1 on supported 64-bit platforms.
  • AttributeError, UnicodeError: If query text cannot be encoded as UTF-8; pass a Unicode str.
  • VelrError: If the transaction is closed, the runtime reports a query error, or the runtime does not expose the transaction query-options/parameter support required for requested row caps, parameters, deadlines, or cancellation.

def savepoint_named(self, name: str) -> Savepoint:

Create a transaction-owned named savepoint.

The named savepoint remains active in the transaction even if the returned Python handle is dropped. Use rollback_to(name) or release_savepoint(name) to act on it later by name.

def rollback_to(self, name: str) -> None:

Roll back to a named savepoint.

On success, changes made after the target named savepoint are undone, newer named savepoints are discarded, and the target named savepoint remains active and may be used again.

An unknown name, a finished transaction, or rollback failure raises VelrError. This returns None and does not commit the outer transaction.

def release_savepoint(self, name: str) -> None:

Release a named savepoint.

The named savepoint must be the most recent active named savepoint.

Returns None. An unknown name, out-of-order release, or a finished transaction raises VelrError; changes remain part of the outer transaction.

def commit(self) -> None:

Commit the transaction.

Any still-active named savepoints are released first so that surviving changes inside the transaction are preserved.

After the commit operation consumes the transaction, it can no longer be used, including if that operation reports a failure. A failure while closing children or releasing savepoints can occur before consumption.

Closes child result handles. Commit failures raise VelrError; the transaction cannot be reused after the commit operation consumes it.

def rollback(self) -> None:

Roll back the transaction.

After this call, the transaction can no longer be used.

Closes child result handles. Runtime failures or a finished transaction raise VelrError. Returns None.

def close(self) -> None:

Close this transaction, rolling back any uncommitted changes.

Also close child streams, result tables, row iterators, and explain traces. Calling close() after commit, rollback, or a previous close is harmless. It returns None; use commit() to retain changes.
